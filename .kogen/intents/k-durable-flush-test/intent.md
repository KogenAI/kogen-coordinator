# Fail a check when Kogen stops flushing its records

Slug: k-durable-flush-test
Model: not applicable — the change adds tests and a caller check to a one-shot switch; there is no state machine beyond "syncing on" until a permitted test-file call turns it off
Acceptance:
- .kogen/intents/k-durable-flush-test/acceptance.feature
- features/steps/k-durable-flush-test__checks.js

Kogen flushes its private records to stable storage through `durable.Sync` (`durable/durable.go`), and Go test binaries switch the flush off with `durable.SkipSyncInTests()`. Today no check fails if a record write stops calling `durable.Sync`, or if a non-test Go file calls `SkipSyncInTests` (observed: replacing the `durable.Sync(` call in `project/provenance.go` with a no-op leaves `go test -count=1 ./project/` passing; `durable/durable_test.go` tests only the observer seam and `contract/durable_test.go` only that syncing is skipped after the switch).

Of the writes the request lists (checkpoint, provenance, stage, context, material and recovery writes), only the provenance write lives in this repository: `project.PublishSource(root, slug string, doc map[string]any) error` in `project/provenance.go`, whose helper `privateWrite` flushes, with `durable.Sync`, both the receipt's temp file `<receipt>.tmp` before it is renamed over the receipt and the archive `<sha256 of the old receipt>.json` of a previous receipt. The checkpoint, stage, context, material, recovery and Shape window writes are in other Kogen repositories and are not changed here.

After this change:

1. **Provenance flush test.** A Go test in package `project` (in `project/provenance_test.go`) watches `durable.Sync` with `durable.ObserveSyncInTests` (removing the observer with `t.Cleanup`) and calls `PublishSource` twice for one Intent with two different docs. It requires that the first publication flushes the receipt's temp file holding the new receipt's bytes at the moment of the flush, and that the second flushes the archive holding the first receipt's bytes and the receipt's temp file holding the second receipt's bytes. For each missing flush it fails with a message containing `provenance write was not flushed with durable.Sync` followed by which file was not flushed. The test passes on the current, flushing code. Replacing every `durable.Sync(` call in `project/provenance.go` with a call that does not flush makes `go test -count=1 ./project/` fail with that text.

2. **Static caller check.** A Go test in package `durable` scans the module that contains it (the folder with `go.mod`, the parent of `durable/`): it walks every folder, skipping folders whose names start with `.` or `_` and folders named `testdata` (the folders Go ignores), parses with `go/parser` every file whose name ends in `.go` and not in `_test.go`, and fails once per call expression whose function is the identifier `SkipSyncInTests` or a selector `<x>.SkipSyncInTests`, with the message `durable.SkipSyncInTests called from non-test file <path>`, where `<path>` is the file's slash-separated path relative to the module root (for example `durable.SkipSyncInTests called from non-test file route/kogen_skip_sync.go`). A file that does not parse fails the test with its path. The declaration of `SkipSyncInTests` and comments that mention it are not calls. On today's tree the test passes: the only callers are `contract/main_test.go` and `contract/durable_test.go`.

3. **Runtime caller check, for every Kogen repository.** Every Kogen repository uses this `durable` package, so `durable.SkipSyncInTests` itself refuses a non-test caller: it reads its caller's file with `runtime.Caller(1)` and, unless that file name ends in `_test.go`, panics before switching syncing off. The panic value is a string or error whose text is `durable.SkipSyncInTests called from non-test file <file>`, `<file>` being the file name `runtime.Caller` reports (absolute, or module-path-relative under `-trimpath`). After the panic syncing stays on: `durable.Sync` still flushes. A call from a `_test.go` file switches syncing off for the rest of the process, as today, so the test suites that call it from their test mains (here `contract/main_test.go`; in kogen, kogen-shaping and kogen-build their `main_test.go`) keep syncing off and take no longer. A non-test helper file called from a test is refused like any non-test file. No option or setting changes this.

The doc comment of `SkipSyncInTests` states the refusal. `durable.Sync` and `durable.ObserveSyncInTests` are unchanged. `project.RestoreSource` (a rollback with `os.WriteFile`) is unchanged.

## Decisions
- A removed flush of the provenance write fails with a message containing `provenance write was not flushed with durable.Sync`. (source: request)
- A non-test caller of `SkipSyncInTests` is named as `durable.SkipSyncInTests called from non-test file <path>`, by the static check (path relative to the module root) and by the runtime check (path `runtime.Caller` reports). (source: request)
- Syncing stays off in test binaries that call `SkipSyncInTests` from a `_test.go` file; no new option. (source: request)
