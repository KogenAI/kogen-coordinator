# Undo a landed commit that lost its Intent trailer

Slug: coord-commit-trailer-survives-hooks
Model: not applicable — one more read-only condition inside the existing post-commit landed check of a single commit; no new state, transitions or interacting rules
Acceptance:
- .kogen/intents/coord-commit-trailer-survives-hooks/acceptance.feature
- features/steps/coord-commit-trailer-survives-hooks__commit.js

The Build's commit message is `git.CommitMessage(title, slug)`: the Intent title, an empty line and the single trailer `Kogen-Intent: <slug>` (`git/commit.go`). `git.Repo.Commit` writes it to `CommitSpec.MessageFile`, runs a plain `git commit -q -F <file>` (the user's hooks apply) and then checks the landed commit in the unexported `landed`. Today `landed` compares the parent with `CommitSpec.Start`, the tree with `CommitSpec.Tree`, and requires a signature when `commit.gpgsign` is true. It never reads the message. A commit-msg or prepare-commit-msg hook that drops or replaces the trailer, or adds another `Kogen-Intent` line, therefore leaves a landed commit that trailer-reading tools cannot attribute to its Intent, and `Commit` reports success.

After the change, `landed` also reads the landed commit's message. It requires exactly one `Kogen-Intent` trailer whose value is exactly `CommitSpec.Slug`. Trailers are what Git's own trailer parser reports for the commit, i.e. the final trailer block, which is how trailer-reading tools see the commit. One way to read them is `git log -1 --no-show-signature --format='%(trailers:key=Kogen-Intent,valueonly,separator=%x00)' <head>`. Git matches the key case-insensitively and trims the value. On this machine (Git 2.54.0) that command printed `add-app\n` for the unchanged message, `add-app\0other-slug\n` after a second line was appended, and `\n` once the trailer was removed. Other trailers a hook appends (for example `Signed-off-by:`) are allowed, and so is a changed title or body.

If the check fails, the commit is undone with the existing compare-and-swap (`undo`: `git update-ref -m "kogen: undo the unverified commit" HEAD <start> <made>`), so it stays in the reflog. `Commit` then returns `""` and a `*sys.Error` with the same class as the other hook changes: `Class: "candidate"`, `Reason: "hook_changed_commit"`, `Exit: 1`, no `Lines`. The working tree and the index are left as the commit left them, as for the other hook failures. The `Detail` is exactly one of the following, where `<slug>` is `CommitSpec.Slug`:

- no `Kogen-Intent` trailer: `a commit hook changed the commit message: it no longer carries the Intent trailer Kogen-Intent: <slug> (no Kogen-Intent trailer found); the commit was undone and the changes are left in place`
- one trailer with another value `<found>`: `a commit hook changed the commit message: it no longer carries the Intent trailer Kogen-Intent: <slug> (found Kogen-Intent: <found>); the commit was undone and the changes are left in place`
- two or more trailers, whatever their values: `a commit hook changed the commit message: it no longer carries the Intent trailer Kogen-Intent: <slug> (duplicate Kogen-Intent trailers: <v1>, <v2>[, ...]); the commit was undone and the changes are left in place`. The values are listed in message order, joined by `, `.

Precedence: the existing parent, tree and signature check runs first and keeps its detail. Example: a pre-commit hook stages `hook-made.txt` and a commit-msg hook drops the trailer. The detail is `a commit hook changed hook-made.txt; the commit was undone and the changes are left in place`. The trailer check, like the other queries, runs before the final `s.Err()` interrupt check, so an interrupt during it still undoes the commit.

Unchanged: `CommitMessage` and the message bytes Kogen writes. Without hooks, the landed message is byte-for-byte `Add the app\n\nKogen-Intent: add-app\n` for the title `Add the app` and slug `add-app`. Also unchanged: `CheckCommitMsg`, `CommitPaths`, the existing details, the exported API (no new exported names) and the interrupt handling. Update the `Commit` and `landed` doc comments so that the `candidate/hook_changed_commit` line names the Kogen-Intent trailer next to the parent, tree and signature. Out of scope: consumers' rendering of the error, goldens, the contract suite's existing tests.

## Decisions
- After the commit, the landed check requires exactly one `Kogen-Intent:` trailer whose value is the Build's slug. Other appended trailers (e.g. `Signed-off-by:`) and a rewritten title still land (source: request)
- A missing, different or duplicated trailer has the commit undone with the existing compare-and-swap. The error is the same class as the other hook changes (`candidate/hook_changed_commit`, exit 1) and the changes stay in place (source: request)
- The reason says the commit message no longer carries the Intent trailer. It names the missing trailer, gives the expected and found values, or says duplicate (source: request)

## Tests
- No hooks: the commit lands with exactly `CommitMessage`'s bytes and one trailer: the existing `TestCommitLandsTheReviewedTree` in `git/commit_test.go` and `TestCommitLandsTheReviewedTreeWithTheIntentTrailer` in `contract/git_commit_test.go`, plus the acceptance scenario (existing)
- A hook that appends `Signed-off-by:` or rewrites only the title still lands: add a table-driven test in `git/commit_test.go` with commit-msg hooks on the `candidate` fixture, checking the returned head and the message (integration)
- A commit-msg or prepare-commit-msg hook that removes the trailer has the commit undone with the "no Kogen-Intent trailer found" detail, HEAD at the start, the undo in the reflog and the edits in the work tree: add a test in `git/commit_test.go` covering both hook names (integration)
- A hook that replaces the slug has the commit undone with the "found Kogen-Intent: <value>" detail: add a test in `git/commit_test.go` (integration)
- A hook that appends a second `Kogen-Intent:` line (another value or the same slug) has the commit undone with the "duplicate Kogen-Intent trailers: ..." detail: add a test in `git/commit_test.go` (integration)
- A tree change by a hook keeps the existing detail when the trailer is also gone: the acceptance precedence scenario; the existing `TestCommitUndoesACommitWhoseHookChangedTheTree`, `TestCommitUndoesACommitThatIsNotSignedWhenTheUserSigns` and `TestCommitUndoesACommitWithAnotherParent` keep passing unchanged (existing)
- The end-to-end behavior through `git.Repo.Commit` on real repositories with real hooks: the acceptance scenarios through a Go driver built from the repository root (integration)

## Feasibility
- Git's trailer parser gives the needed distinctions on real hook-rewritten commits (`git commit -q -F` with `core.hooksPath`, Git 2.54.0). `%(trailers:key=Kogen-Intent,valueonly,separator=%x00)` printed `add-app` for no hook, an appended `Signed-off-by:` and a reworded title. It printed an empty line after a commit-msg or prepare-commit-msg hook removed the trailer, `other-slug` after replacement, and `add-app\0other-slug` after a second line was appended. A lower-case `kogen-intent: add-app` key still reported `add-app`. Raw commit messages were exactly the bytes the scenarios expect. (probe: exit 0)
- On the unchanged tree, the draft feature ran 9 scenarios. 4 passed: no hooks, Signed-off-by, title rewrite and precedence. 5 failed only at the undone step with "Commit landed <id> instead of failing with candidate/hook_changed_commit". Every "the commit Kogen made has the message" step passed, so each hook fixture did rewrite the message as expected. That is the legitimate missing-feature red. (probe: exit 1, 7.4 s)
- The step file runs a Go driver it generates and builds, and makes several assertions per scenario. Its observer control runs the same driver and checks on two fixtures that behave the same before and after the change: no hooks (lands) and a post-commit hook that adds a commit on top (undone, existing detail). good pairs each check with the true fixture; bad swaps them, or expects the message with `other-slug`.
