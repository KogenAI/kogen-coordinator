# Check the rules context before token lookup

Slug: rules-cancelled-context-before-token
Model: not applicable — one preflight decision changes; there is no new state or lifecycle.
Acceptance:

- features/steps/rules-cancelled-context-before-token__driver/main.go

For a configured project, `rules.Load(ctx, root, opts)` must honor an already-done context before looking up the Studio token. Return `(nil, ctx.Err())` directly, without making an HTTP request or consulting the cache. This replaces the current missing-token refusal for calls whose context is already cancelled or expired (ev-5a1728f3). Active-context token refusal, configuration errors, in-flight cancellation handling, and outage and cache policy stay unchanged. Production and implementation-test edits are limited to `rules/rules.go` and `rules/rules_test.go`.

The acceptance driver calls the exported `rules.Load(context.Context, string, rules.Options) (*rules.Snapshot, error)` with a fresh temporary project and a local `httptest` server, using `rules.ConfigPath` and the optional `Client` and `Getenv` seams. The fixture uses the existing empty-rules response `{"product":"kogen","repo":"r","rules":[]}` (evidence: rules/rules_test.go). A successful live load with a synthetic token primes the same-scope cache; an active load against HTTP 503 verifies it. The driver then serves those exact cache bytes at the cache path over a test-only named pipe: the writer can open only when a reader opens and records that event before writing any bytes. If there was no measured read, the driver drains the pipe after measuring so its writer can exit. This catches a cache read even if Load discards the result. The measured load uses a getter that supplies the absent-token value and records invocation, and an HTTP client that counts even transport attempts that do not reach the server. Cucumber checks the resulting lookup, request and cache-read observations and compares the returned snapshot and error with the feature's expectations. Context errors are checked by exact sentinel identity, not by text or `errors.Is`.

## Decisions
- After configuration succeeds, a cancelled or expired context takes precedence over token lookup and returns ctx.Err() itself, with no snapshot or rules error and without making a request or consulting the cache. (decision: D1, round 1) (evidence: rules/rules.go; rules/rules_test.go) (source: request)
- Preserve active-context missing-token refusal, existing configuration handling, the existing pre-fetch and in-flight context checks, and outage and cache policy. (decision: D2, round 1) (evidence: rules/rules.go; rules/config.go; rules/rules_test.go) (source: request)

## Tests
- A context already cancelled or deadline-expired bypasses token lookup and returns the exact sentinel with no snapshot or HTTP attempt even with a verified cache: add a table-driven `Load` regression to `rules/rules_test.go`, using a context cancelled before invocation or a deadline already in the past and observing `Options.Getenv` and requests (regression)
- Either already-done context must not consult the cache even if it would discard the data: the owned Cucumber scenarios observe reads of the test-only cache pipe (scenario)
- An active missing-token load still refuses without an HTTP request or cache result: retain `TestRefusedNeverReadsCache` in `rules/rules_test.go` and exercise the active control through the acceptance driver (existing)
- Ordinary outages still use the verified cache under the existing policy, and existing valid-token cancellation handling is preserved: retain `TestOutageUsesVerifiedSameScopeCache`, `TestCancelledContextReturnsContextError`, `TestExpiredDeadlineReturnsContextError`, and `TestCancelledDuringRequestReturnsContextError` in `rules/rules_test.go` (existing)
