# Reject unknown resume checkpoint stages

Slug: route-resume-stage-validation
Model: not applicable — validation of a single stage argument adds no state or lifecycle.
Acceptance:
- .kogen/intents/route-resume-stage-validation/acceptance.feature
- features/steps/route-resume-stage-validation__resume.js
- features/steps/route-resume-stage-validation__driver/main.go

`route.Resume[E, A](ctx context.Context, s route.Steps[E, A], stage string) error` must refuse a stage it does not recognize for resume. Return a non-nil error whose message names the offending stage, before invoking any `Steps` method, including `Continuable`. No particular error type or wording is required beyond naming the stage. This replaces the catch-all that silently sent such inputs to `Continue` or `Fresh` depending on reviewer capability (ev-8e249299; evidence: route/route.go).

The documented resume inputs are `StageCommitFailed` (`commit_failed`), `StageReviewOnly` (`review_only`), and the three review stages `StageReview` (`review`), `StageReviewVerify` (`review_verify`), and `StageReviewRetry` (`review_retry_verify`). The three review stages continue when the reviewer can continue; otherwise prepare fresh evidence with the original stage and review it. `StageReviewOnly` always prepares fresh evidence and reviews it. These review paths commit with restart enabled. `StageCommitFailed` still loads the saved approval and commits it alone with restart disabled. `StageCommit` and `StageLanded` remain persisted lifecycle names, not additional resume paths. Preserve existing cancellation, step errors, and restart-on-drift semantics for valid inputs (evidence: route/route.go; route/route_test.go; contract/route_test.go).

Limit production and implementation-test edits to `route/route.go` and `route/route_test.go`. Update the `Resume` documentation with the validation rule. No changes to `Cycle`, `Steps`, persisted names, or the implementer’s own checkpoint stages or routing. Neither required implementation file is in the configured protection or this Intent's acceptance baseline (evidence: .kogen/project.yaml).

Acceptance builds the owned Go helper from the module root with `go build -o <temporary binary> ./features/steps/route-resume-stage-validation__driver` and runs that binary with the feature's stage and continuable flag as arguments. Each invocation starts a fresh `Steps[string, string]` fake and calls the public `Resume` with `context.Background()`. The fake records all method calls in order and simulates a successful commit without drift. The driver emits one JSON object: `error` is null for a nil error, otherwise the error string; `calls` is an ordered array of strings, empty if untouched. The scenarios assert both the stage-bearing error and an empty call array on refusal. For accepted stages they assert no error and the exact ordered phase trace (excluding capability queries, which are not part of the valid-path assertion). Go 1.27.2 or newer and the configured Node/Cucumber runner are used; no service or credential is needed (evidence: go.mod; .kogen/project.yaml).

## Decisions
- Refuse an unrecognized checkpoint stage before calling any step, including Continuable, and include the offending stage in the error for either reviewer capability. (decision: D1, round 1) (evidence: route/route.go; route/route_test.go) (source: request)
- Preserve the documented review and failed-commit resume paths, with the existing persisted names and no changes to the implementer’s own checkpoint stages. (decision: D2, round 1) (evidence: route/route.go; route/route_test.go; contract/route_test.go) (source: request)
