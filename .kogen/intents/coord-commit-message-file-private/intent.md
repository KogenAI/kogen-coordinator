# Create the commit message file private

Slug: coord-commit-message-file-private
Model: not applicable — one file created exclusively and removed around a single git commit command; no persistent state, transitions or interacting rules
Acceptance:
- .kogen/intents/coord-commit-message-file-private/acceptance.feature
- features/steps/coord-commit-message-file-private__commit.js

`git.Repo.Commit` (`git/commit.go`) writes the Build's commit message, `CommitMessage(spec.Title, spec.Slug)`, to the caller-chosen path `CommitSpec.MessageFile` (kogen-build passes the run's `commit-message.txt`) and then runs `git commit -q -F <file>`. Today it uses `os.WriteFile(spec.MessageFile, ..., 0o644)` after `ReadTree`, and never removes the file. If the path already exists as a symbolic link, the write goes through it to the link's target; while the file exists it is world-readable; and a leftover file from an earlier interrupted commit is silently overwritten in place (keeping its old mode).

After the change, `Commit` prepares the message file itself, before any Git command runs (after the existing read-only and `checkRev` checks, before `ReadTree`):

- It inspects the path without following a link (`os.Lstat`).
  - Nothing there: the file is created.
  - A regular file (a leftover): it is removed, then the file is created (remove-then-create, never written in place).
  - A symbolic link (whether its target exists or not): `Commit` returns `""` and the plain (non-`*sys.Error`) error with exactly the text `git: refusing the commit message file <path>: it is a symbolic link`, where `<path>` is `CommitSpec.MessageFile` as given.
  - Any other non-regular file (directory, named pipe, socket, device): `Commit` returns `""` and the plain error `git: refusing the commit message file <path>: it is not a regular file`.
  - Any other `Lstat` error is returned as it is.
- On a refusal nothing is changed: no Git command runs (the index and HEAD are untouched), the link, its target (existing or missing) and the directory are left exactly as they were.
- The file is created exclusively: `os.OpenFile(path, os.O_WRONLY|os.O_CREATE|os.O_EXCL, 0o600)` (exclusive creation never follows a link, and fails if anything appeared at the path in between; that error is returned as it is). Its permission bits are exactly `0600` while git runs, whatever the process umask (for example by `File.Chmod(0o600)` on the open file). The message bytes are exactly `CommitMessage(title, slug)` as today. If writing or closing fails, the created file is removed and the error returned.
- Once created, the file is removed (`os.Remove`, error ignored) before `Commit` returns, on every path: a landed commit, `environment/commit_failed`, a `*git.TimeoutError`, `*sys.Interrupted`, `candidate/hook_changed_commit`, a `ReadTree` error and any other error.

Unchanged: the message text, `CommitMessage`, the `git commit -q -F <file>` command and its options, the landed checks, the undo of a landed commit, every existing error class, reason, exit, detail and lines (for example `environment/commit_failed`, exit 3, detail `git commit failed (status 1); the verified changes are left uncommitted`, Git's output as lines), the timeout text `git commit -q -F <file> timed out after <bound>`, and the exported API (no new exported names). `CheckCommitMsg` and `CommitPaths`, which already write their own `0600` temporary files and remove them, are out of scope. Update the `CommitSpec.MessageFile` and `Commit` doc comments to say the file is created private (0600, exclusively, a regular leftover replaced, a link or other non-regular file refused before any Git command) and removed before `Commit` returns.

This deliberately changes what callers can observe: the message file no longer exists after `Commit` returns, even after a landed commit. The landed message stays readable from the commit itself (`git log -1 --format=%B`). In this repository, update the tests that read the file after a landed commit to assert instead that nothing exists at the path: `TestCommitLandsTheReviewedTree` in `git/commit_test.go` (the `message file` assertion) and the contract test `TestCommitLandsTheReviewedTreeWithTheIntentTrailer` in `contract/git_commit_test.go` (the `message file` assertion). In `contract/README.md`, extend the `commit-message` item to say the message file is created with mode 0600 and removed after the commit, and replace the "No difference was found" sentence under "Differences from consumer expectations" with a sentence saying that kogen-build's `TestCommitLandsTheReviewedTree` reads the message file after a landed commit, which this change deliberately removes. kogen-build is not in this repository and is not changed here. Delivery's consumer gate refused an earlier candidate of this change because kogen-build `TestCommitLandsTheReviewedTree` (`git_commit_test.go:62: open commit-message.txt: no such file or directory`) reads the file after `Commit`; that consumer test pins the removed behaviour, so keep the removal and end the Build's final summary with exactly this line:

`consumer-first: kogen-build TestCommitLandsTheReviewedTree: stop reading the commit message file (commit-message.txt) after Commit returns; Commit now removes it on every outcome, so read the landed message from the commit (git log -1 --format=%B) instead`

## Decisions
- The message file is created exclusively with mode 0600; a symbolic link or other non-regular file at the path fails the commit; a regular leftover file is replaced by remove-then-create (source: request)
- The message file is removed after the commit whether it succeeded, failed or was interrupted (source: request)
- Message text, commit behaviour and error classes are unchanged; a refusal names the path and the reason (source: request)
- A refusal names the path and the reason with exactly `git: refusing the commit message file <path>: it is a symbolic link` or `git: refusing the commit message file <path>: it is not a regular file`, returned as a plain error like the former message-file write failure; the exact texts are fixed in shaping (source: request)
- The file is prepared before `ReadTree`, so a refusal runs no Git command at all ("git is not run") (source: request)
- A path that exists as a symbolic link whose target is missing is refused like any other link and its target is not created (source: request)
- The removal after a landed commit is kept although kogen-build's `TestCommitLandsTheReviewedTree` reads the file; following the retry note, the Build reports it with the `consumer-first:` line above (source: request)

## Feasibility
- The fake git first on PATH sees every Git command `Commit` runs: both `Repo.gitBinary` (direct commands such as `read-tree`) and the shell `git commit -q -F <file>` resolve `git` from the repository's PATH. With the log emptied just before `Commit`, a read-only repository's refusal left it empty, and a normal commit logged `commit -q -F <file>`. (probe: exit 0)
- On the unchanged tree, the fake git commit saw the leftover 0600 file as `600` with the new message (in-place truncation), `fail` gave `environment/commit_failed` exit 3 with detail `git commit failed (status 1); the verified changes are left uncommitted` and lines `["fake git commit refuses"]`, and `hold` with a SIGINT `Session.Interrupt` gave `*sys.Interrupted` `SIGINT` with HEAD at the start. These outcomes do not depend on the change, so the observer control uses them. (probe: exit 0, 1.8 s)
