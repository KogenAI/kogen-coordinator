# Leave the approved Intent out of a Build's edits

Slug: k-interrupt-edits-exclude-approved
Model: not applicable — a pure predicate and an order-keeping filter over a given path list; no state, transitions or interacting rules
Acceptance:
- .kogen/intents/k-interrupt-edits-exclude-approved/acceptance.feature
- features/steps/k-interrupt-edits-exclude-approved__driver.js

An interrupted Build reports `edited: <paths>` and the person discards those paths. Today kogen-build computes that list as the whole tree diff `repo.Changed(b.StartTree, tree)` (kogen-build `build/stop.go`, `details`). The Build's first verification, `promoteModel` (kogen-build `build/maintained.go`, called first in `Verify`), writes `.kogen/models/<slug>/model.qnt` and `.kogen/models/<slug>/model.json` after the start tree was taken, so those files appear in the list. Discarding them leaves an empty `.kogen/models/<slug>/` folder, so the next Build's `promoteModel` skips the folder and its read of `model.json` fails: `open …/.kogen/models/<slug>/model.json: no such file or directory` (the live failure of 4 Nov, `controller/internal_error`, exit 70). The coordinator gains the one rule for which files belong to the approved Intent and the Build edit list that leaves them out.

After this change, package `project` has two new exported functions, in a new file `project/edits.go`:

- `func OwnedByIntent(slug, path string) bool` reports whether the repository-relative, slash-separated `path` is one of the Intent `slug`'s own files. It returns true exactly when `path` starts with `IntentDir(slug) + "/"` (`.kogen/intents/<slug>/`) or with `.kogen/models/<slug>/`. The comparison is byte-exact on the prefix including its final `/`. So `.kogen/models/complete-task-archive/model.json` and `.kogen/intents/complete-task-archive/intent.md` are not owned by `complete-task`, and neither is `lib/complete-task/model.json`. It touches neither the filesystem nor Git.
- `func BuildEdits(slug string, changed []string) []string` is a Build's edit list. It returns the paths of `changed` for which `OwnedByIntent(slug, p)` is false, in their order in `changed`. `changed` is the list `git.Repo.Changed(startTree, candidateTree)` returns. With no remaining paths (including a nil or empty `changed`), the result has length 0. It returns no error and touches neither the filesystem nor Git.

Worked example (the 4 Nov run as acceptance replays it): the tree diff `[.kogen/models/complete-task/model.json, .kogen/models/complete-task/model.qnt, README.md, lib/task.js, test/task.test.js]` gives the edit list `[README.md, lib/task.js, test/task.test.js]`. After those three are discarded, the model files stay in the working tree. A Build's dirty check that counts `OwnedByIntent` paths as the Intent's own finds nothing else changed, the second start tree holds both model files, and `model.json` reads back with path `.kogen/models/complete-task/model.qnt`.

Unchanged: `git.Repo.Changed` stays the whole tree diff (the commit path in `git/commit.go` relies on it), and so do `IntentDir`, `ModelPath`, `git.Repo.Tree` and `ChangedPaths`. No golden, recorded hash or baseline list changes. The contract suite pins the new behaviour for kogen-build, its consumer. `contract/intent_test.go` gains `TestBuildEditsLeaveOutTheApprovedIntent`, which asserts the `OwnedByIntent` cases and the `BuildEdits` order of the filter scenario. `contract/README.md` gains a "Behaviours and formats pinned" item `build-edits` naming that test. Kogen-build's own use of these functions is a paired consumer change in the kogen-build repository: its interrupted-stop list in `build/stop.go` and its dirty check `cleanPaths` in `build/build.go`. This Intent does not edit kogen-build.

Acceptance builds (`go build -o`) a Go driver that the step file generates in a temporary folder of the module and runs it once per case. In a fresh Git repository it replays the 4 Nov sequence: an approved Intent with a model, the start tree, `promoteModel`'s writes, builder edits, the interrupt, the discard of every listed path and the start of a second Build. It reaches the new functions through a small `seam.go`. On today's tree the build fails with `undefined: project.BuildEdits`, so both scenarios fail at their When step.

## Decisions
- An interrupted Build's edit list, and so what the person is told to discard, contains only the Build's own changes and never a path under `.kogen/intents/<slug>/` or `.kogen/models/<slug>/` of the approved Intent (source: request)
- After the listed edits are discarded, a second Build starts and reads `.kogen/models/<slug>/model.json` (source: request)
- The live regression of 4 Nov is kept as an offline acceptance scenario (source: request)

## Tests
- `OwnedByIntent` is true under `.kogen/intents/<slug>/` and `.kogen/models/<slug>/` and false for a slug sharing the same leading characters (`complete-task-archive`) and for other paths: new test in `project/edits_test.go` (unit)
- `BuildEdits` leaves out exactly the owned paths, keeps the order of `changed`, and gives length 0 for nil input: new test in `project/edits_test.go`, plus `TestBuildEditsLeaveOutTheApprovedIntent` in `contract/intent_test.go` with the `build-edits` item in `contract/README.md` (unit)
- The 4 Nov interrupted Build: model files that `promoteModel` writes after the start tree are in `Changed(start, tree)` but not in `BuildEdits`, and after the listed edits are discarded `.kogen/models/<slug>/model.json` still reads back: new Git-fixture test in `project/edits_test.go` and acceptance scenario "The interrupted Build of 4 Nov lists only its own edits and a second Build reads the model" (regression)
